# Project 1: Scratch Remix

**CS1 — Ms. Jergens**

---

## Summary

**Learning Goal:** Remix an existing Scratch game and transform it into something creative and distinctly your own. The goal is to deepen your understanding of sequences, variables, conditions, loops, and custom blocks using Scratch's block-based coding environment.

Remixing is a real programming practice — studying working code and building on it. The challenge is not just to change a few colors or sprites, but to reimagine the game so thoroughly that someone who played the original would not recognize yours.

---

## Step 1: Choose Your Base Project

Remix one of these two games:

- [Sword Throw on Scratch](https://scratch.mit.edu/projects/1142834613/editor/)
- [Jetpack Wars on Scratch](https://scratch.mit.edu/projects/1143749214)

Play both before deciding. Click the **Remix** button on the one you choose to create your own editable copy.

Before coding, study the original:
- What is the objective?
- Where do you see loops, conditions, and variables in the code?
- What would you change first?

---

## Step 2: Transform It

Your remix must be **unrecognizable** from the original. All of the following changes are required:

| What to change | Requirement |
|---|---|
| Theme & story | Completely different setting, characters, and narrative |
| Sprites | All new sprites — none from the original |
| Background | New background(s) |
| Scoring | Change how points are earned, or replace with a different win condition |
| At least one new mechanic | Add something the original does not have (obstacle, power-up, timer, level, etc.) |

A surface-level remix — same gameplay with new pictures — will not receive full credit. The code structure can stay similar, but the experience must feel like a new game.

---

## Programming Requirements

Your remix must clearly demonstrate all of the following:

**Sequences** — Logical, step-by-step instructions controlling sprites and the stage.

**At least one loop** — Use `forever` or `repeat` blocks for continuous or repeated behavior.

**At least two conditions** — Use `if` or `if...else` blocks to make decisions based on input, collisions, score, etc.

**At least one variable** — Create and use at least one variable (score, lives, timer, speed, health, etc.).

**Custom block (Make a Block)** — Create and use at least one custom block to organize a reusable chunk of code (animation, movement pattern, scoring routine, etc.).

**User interaction** — The player must control something using keyboard, mouse, or other input.

**Win / Lose condition** — A clear way to win and/or lose, with appropriate messages or ending screens.

## Level-Up (Optional)

**Small:** Add a scoring system with multiple variables; create smooth sprite animations.

**Medium:** Multiple levels; power-ups or different game modes; timer; custom block with parameters.

**Advanced:** Save high score with a list or cloud variable; procedural generation (random obstacles); multiplayer elements.
